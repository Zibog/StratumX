# Editor Morphology Workspace And Stage Flow Canon

**Stack version:** `SX-CANON/1.0.24/STACK-v30`

## Purpose
Freeze the editor as a believable production workstation.

This canon does not ask for one more debug shell.
It asks for:
- Unreal-grade seriousness in viewport and world editing;
- CapCut-like stage flow for common sequential work;
- Cursor-like assistant and extension presence without truth leakage.

## Shell law
The editor must feel like one coherent product:
- one main shell;
- one active project and world identity;
- one stage strip;
- one honest primary viewport;
- docked panels that can detach without becoming parallel truths.

## Canonical stage strip
The default top strip is:
1. Project
2. World
3. Materials
4. Simulation
5. Diagnostics
6. Capture
7. Build

The strip is a workspace selector, not a mode prison.
Every stage reuses the same project/world truth and same primary viewport.

## Morphology law
The editor shell must include:
- stable menu bar;
- compact top toolbar;
- stage strip below the toolbar;
- dominant central viewport;
- docked left navigation surfaces;
- docked right details/inspector surfaces;
- bottom diagnostics/content/capture rail;
- optional detached secondary windows.

## No-self-made-chrome law
The shell may not look like a developer utility with random buttons.
It must have:
- stable window chrome;
- stable spacing;
- lawful docking;
- predictable focus handoff;
- obvious recovery when a panel or stage is unavailable.

## Sequential-flow law
Common work should read as:
`open project -> open world -> inspect terrain/sky -> bind materials -> simulate -> diagnose -> capture -> build`

The shell may expose deep labs.
The common route must not require entering them first.

## Assistant and extension law
The shell permanently reserves:
- one assistant dock;
- one extension manager surface;
- one capability-grant model;
- one apply/revert lane for assistant-suggested actions.

Neither assistant nor extensions may become private truth islands.
