# V33 readiness statements

Stack version: `SX-CANON/1.0.28/STACK-v34`

## V33 readiness rule

A domain may be called `document-gold` only if all six documentation roles exist or are explicitly waived:

1. canonical law;
2. developer implementation guide;
3. user/editor guide;
4. API reference;
5. tutorial path;
6. troubleshooting path.

Netcode is not allowed to claim 100% document readiness in V33. It is raised to a minimum viable 75% spine: enough to guide implementation, not enough to claim mature shipped networking.

# V34 readiness decision

Stack version: `SX-CANON/1.0.28/STACK-v34`

Gold readiness now requires the decision ledger and DCC/source asset support to be reflected in canonical law, developer docs, user docs, API reference, tutorials, troubleshooting, and quality gates.

Domains above 50% readiness must be driven to route-ready document-gold. Domains below 50% must be brought to at least 75% document readiness with explicit remaining gaps. Netcode is staged as 1.0 foundation / 1.x multiplayer execution, not fake 1.0 final multiplayer.
