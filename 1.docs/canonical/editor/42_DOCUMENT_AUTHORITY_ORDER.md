# Document Authority Order

**Stack version:** `SX-CANON/1.0.24/STACK-v30`

## Authority hierarchy
1. global canon and lower-stack law (`engine`, `sdk`, `tooling`)
2. editor constitutions
3. editor root stack/scope/dependency documents
4. editor product, domain, runtime, and family-registry models
5. shared types and boundary rules
6. implementation and testing documents
7. level and family contracts
8. evidence and readiness derivatives

## Reading law
When a level contract is too thin or ambiguous, root product/runtime models win.
When an editor document conflicts with tooling authority, tooling wins immediately.
`43_CANONICAL_FAMILY_REGISTRY.md` is the root-authoritative editor family registry.

## Conflict rule
No evidence note, panel contract, or plugin note may override a root dependency or authority rule.
No family-declared `00_LEVEL.md` contract in the active editor package may claim a canonical family identity that contradicts `43_CANONICAL_FAMILY_REGISTRY.md`.
