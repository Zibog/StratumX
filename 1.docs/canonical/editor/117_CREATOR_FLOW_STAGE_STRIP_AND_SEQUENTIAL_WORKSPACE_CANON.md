# Creator Flow Stage Strip And Sequential Workspace Canon

**Stack version:** `SX-CANON/1.0.24/STACK-v30`

## Purpose
Freeze the sequential stage strip so common creation work feels guided without turning the editor into a locked wizard.

## Canonical macro stages
- World
- Simulation
- Capture

Future wider stages may exist, but these three close the first honest production contour.

## Canonical world-stage conveyor
Inside **World**, the shell must expose one ordered conveyor:
`Overview -> Terrain -> Vegetation -> Structures -> Groups -> Materials -> Audio -> Weather/Lighting -> Validation -> Build Ready`

This ordered flow is mandatory as a shell affordance even when individual creators jump nonlinearly.

## Flow law
The strip supports one common conveyor:
`World -> Simulation -> Capture`

### World stage
Project/world open, terrain, vegetation, structures, grouped props, materials, audio, weather, lighting, and validation.

### Simulation stage
Preview, audibility, immediate consequence, play/simulate context, runtime posture, timeline review, and causal debugging.

### Capture stage
Compare, capture, evidence append, freeze blockers, certification-ready views, and release-facing review.

## Layout law
Each stage may bias panel visibility, but:
- the primary viewport remains present;
- the project/world identity remains constant;
- stage switching must not reset the user into layout chaos.

## Wayfinding law
The strip must communicate:
- which stage is active;
- which world-substep is active when in World;
- which dependent steps are incomplete or stale;
- whether a stage or substep is blocked by missing truth, stale bake, or validation failure.

## Why this exists
The strip makes the editor feel human:
- strong like a serious engine editor;
- sequential like a creator tool;
- extensible like a modern assistant-aware workspace.
